# K-Visa Assist — 서비스 상세 기획서 (Service Specification)

> 전제: 운영 주체는 **변호사 겸 행정사 자격을 보유한 단일 사무소**.
> 모든 상담·수임·접수를 자체 처리하므로 알선·중개 이슈 없음 (`docs/LEGAL_REVIEW.md` §3.4).
> 본 문서는 `PLANNING.md`(초안) → 실제 개발 착수를 위한 상세 명세입니다.

## 1. 서비스 정의

### 1.1 포지셔닝
**"AI로 상담받고, 변호사에게 맡기는 비자 서비스"**

| 요소 | 내용 |
|---|---|
| 운영 주체 | 변호사·행정사 사무소 (출입국민원 대행기관 등록) |
| 고객 약속 | ① 24시간 다국어 AI 상담 ② 정확한 서류 준비 ③ 접수 대행 ④ 거절 시 불복 절차까지 원스톱 |
| 차별점 | 일반 행정사 사무소와 달리 **비자 거절 → 이의신청·행정심판·행정소송**까지 한 사무소에서 처리 가능 (변호사 자격) |
| 과금 | 대행 보수(비자 유형별 정액) + 정부 수수료 실비. 상담·견적까지는 무료 |

### 1.2 서비스 범위 (MVP 대상 비자)
초기에는 수요가 크고 절차가 정형화된 유형에 집중:

| 코드 | 유형 | 업무 | 우선순위 |
|---|---|---|---|
| D-2 / D-4 | 유학·어학연수 | 신규(국내 변경)·연장 | P0 |
| D-10 | 구직 | 신규·연장 | P0 |
| E-7 | 특정활동(취업) | 신규·변경·연장·근무처변경 | P0 |
| F-2-7 | 점수제 거주 | 변경 | P1 |
| F-6 | 결혼이민 | 신규·연장 | P1 |
| F-5 | 영주 | 변경 | P2 |
| 공통 | 체류지 변경, 재입국허가 등 부수 민원 | — | P1 |

MVP 이후 확장: E-9→E-7-4 전환, D-8(창업), 국적 귀화.

## 2. 사용자 여정 (End-to-End)

```
0. 유입     다국어 랜딩/SEO/커뮤니티 → 앱 진입, 언어 선택 (비회원 상담 가능)
1. 상담     AI 챗봇 인테이크 (§4) → 비자 유형 판정 + 가능성 사전 진단
2. 견적     대행 보수·정부 수수료·소요기간 자동 안내 → 회원가입 유도
3. 수임     전자 위임계약 체결 (위임장·개인정보 동의 전자서명) + 착수금 결제
4. 입력     신청 정보 입력 (챗봇 수집값 자동 채움, 부족분만 폼으로)
5. 서류     자동 생성 체크리스트 → 촬영/업로드 → AI 1차 검사 → 담당자 검토
6. 검토     사무소 최종 검토 → 보완 요청 or 접수 승인 → 잔금 결제
7. 접수     하이코리아 전자민원 또는 방문/사전예약 접수 (사무소 수행)
8. 심사     진행 상태 추적, 출입국 보완요구 대응
9. 결과     승인: 결과 안내 + 다음 만료일 알림 등록
            거절: 사유 분석 → 재신청 or 이의신청·쟁송 상담 (변호사 업무 전환)
10. 유지    만료 90/60/30일 전 알림 → 연장 재수임 (반복 매출 루프)
```

**핵심 전환 지점 KPI**: 상담 완료율(1), 견적→수임 전환율(2→3), 서류 완성 소요일(5), 재수임률(10).

## 3. 화면별 기능 명세

프로토타입(`app/`) 6개 화면을 기준으로 확정 스펙을 정의. (M) = MVP 필수.

### 3.1 홈 `index.html` (M)
- 언어 선택: EN(기본)/KO/VI/ZH — 선택값 전역 저장
- CTA: AI 상담 시작 (비로그인 허용)
- 로그인 시: 진행중 사건 카드(단계·미완료 액션), 만료 임박 알림 배너
- 비자 정보 바로가기, 사무소 소개(변호사·행정사 프로필 — 신뢰 요소)

### 3.2 AI 챗봇 `chat.html` (M)
- 인테이크 대화(§4) + 자유 질문 응답(RAG)
- 메시지 유형: 텍스트, 퀵리플라이, 비자 추천 카드, 체크리스트 카드, 견적 카드, 담당자 연결
- 모든 정보성 답변에 출처(하이코리아 페이지) + "참고용, 최종 검토는 담당 변호사·행정사" 고지
- 대화 내용은 케이스 생성 시 자동 첨부 (담당자가 맥락 파악)
- 에스컬레이션: 신뢰도 낮음/복잡 사안/불복 관련 → 사람 상담 예약으로 전환

### 3.3 비자 정보 `visas.html` (M)
- 비자 유형 카드: 요건, 서류, 수수료, 처리기간, 체류기간, 활동범위
- 데이터는 지식베이스(§5)에서 렌더 — 하드코딩 금지, 갱신일 표시
- 상세 페이지에서 "이 비자로 상담 시작" CTA

### 3.4 신청·서류 `documents.html` (M)
- 케이스별 서류 체크리스트 (지식베이스 requirements → 개인 조건 반영해 생성)
- 항목 상태 머신: `미제출 → 업로드됨 → AI검사통과/실패 → 담당자검토중 → 승인/보완요청`
- 업로드: 카메라/파일, 이미지+PDF, 항목당 다중 파일
- AI 1차 검사(P1): 문서 종류 매칭, 해상도/잘림, 유효기간(여권 등) OCR 확인
- 보완 요청 시 담당자 메모 + 푸시/이메일 알림

### 3.5 진행 상태 `status.html` (M)
- 10단계 여정(§2) 중 현재 위치 타임라인
- 담당자 카드 + 1:1 메시지 스레드 (M) — 카카오채널/이메일 연동(P1)
- 결제 내역, 접수증/영수증 다운로드

### 3.6 마이페이지 `profile.html` (M)
- 프로필(국적, 현재 체류자격, 만료일), 언어·알림 설정
- 만료일 기반 자동 알림 등록 상태 표시
- 약관·개인정보처리방침·사무소 정보(광고 규정 준수 표기)

### 3.7 사무소 관리자 웹 (M — 별도 화면, 데스크톱)
- 케이스 보드: 단계별 칸반 (신규상담/수임대기/서류수집/검토/접수/심사중/완료)
- 케이스 상세: 챗봇 대화 이력, 입력값, 서류 뷰어+승인/보완, 상태 변경, 메모
- 고객 메시징, 결제 확인, 만료 알림 캠페인 관리
- 지식베이스 관리: 하이코리아 변경 감지 알림 → 검수 후 반영 (§5.3)

## 4. AI 챗봇 상세 설계

### 4.1 구조: 하이브리드 (슬롯 인테이크 + RAG 자유응답)

```
사용자 발화
   ├─ 인테이크 모드: 비자 판정에 필요한 슬롯을 대화로 수집 (LLM이 자연어 파싱)
   └─ 질문 모드: 지식베이스 RAG 검색 → 근거 인용 답변
   공통: 매 턴 에스컬레이션 판정 (사람 연결 필요 여부)
```

### 4.2 인테이크 슬롯 정의 (비자 판정 입력값)

| 슬롯 | 예시 | 필수 |
|---|---|---|
| nationality | 베트남 | ✅ |
| current_location | 국내 체류 / 해외 | ✅ |
| current_visa | D-2 (국내인 경우) | ✅ |
| visa_expiry | 2026-09-01 | 국내만 |
| purpose | 취업/유학/결혼/연장… | ✅ |
| education | 학사(전공), 졸업연도 | 취업류 |
| career_years | 경력 연차, 직종 | 취업류 |
| employer_info | 회사 규모, 업종, 고용형태 | E-7 |
| income / finance | 연봉, 잔고 | 유형별 |
| family | 배우자 국적, 혼인일 | F-6 |
| violations | 출입국법 위반·범죄 이력 여부 | ✅ (리스크 판정) |

### 4.3 판정 로직
- 슬롯 충족 시 **룰 엔진**(비자별 요건표를 코드화)이 1차 판정: `적합 / 조건부 / 부적합 / 판단불가`
- LLM은 대화·설명을 담당하고 **판정 자체는 룰 엔진 결과를 따름** (환각으로 인한 오판정 방지)
- 조건부/판단불가/거절이력/위반이력 → 자동으로 사람 상담 예약 플로우
- 판정 결과 + 근거 요건 + 견적을 카드로 제시 → 수임 전환

### 4.4 대화 정책 (프롬프트 원칙)
1. 답변은 지식베이스 근거가 있을 때만 단정, 없으면 "담당자 확인 필요"로 위임
2. 법률 판단(불복 가능성, 위반 사안)은 답변하지 않고 변호사 상담으로 연결
3. 개인정보 최소 수집 고지, 수집 전 동의
4. 언어: 사용자 언어로 응답, 법령·서류명은 한국어 병기 (출입국 제출용)
5. 매 세션 종료 시 요약 카드 생성 → 케이스에 저장

### 4.5 품질 관리
- 골든 시나리오 테스트셋 (비자유형×국적×조건 100+ 케이스) — 판정 회귀 테스트
- 전 대화 로그 검수 큐: 담당자가 주 단위 오답 태깅 → 지식베이스/룰 보완
- 답변 하단 "이 답변이 도움이 되었나요?" 피드백 수집

## 5. 지식베이스 & 데이터 파이프라인

### 5.1 스키마 (핵심 테이블)

```
visa_types        code, name_i18n, category, summary, stay_period, activity_scope
requirements      visa_code, condition_type(학력/경력/소득/기타), operator, value, note
documents_master  visa_code, doc_name_i18n, issuer, condition(항상/조건부), valid_days
fees              visa_code, application_type(신규/연장/변경), gov_fee, processing_days
sources           url, section, fetched_at, hash   ← 모든 레코드가 source_id 참조
```

### 5.2 수집
- 1순위: 공공데이터포털(data.go.kr) 공식 API 확인 → 있으면 API 사용
- 2순위: 하이코리아 공개 페이지 수집 (robots.txt·이용정책 준수, 주 1회 배치)
- 수집물은 원문 스냅샷 보관 (근거 추적성)

### 5.3 갱신 워크플로 (Human-in-the-loop)
```
주간 크롤 → 이전 스냅샷과 diff → 변경 감지 시 관리자 알림
→ 담당자(행정사) 검수·승인 → 지식베이스 반영 → 임베딩 재생성
```
- **검수 없이 자동 반영 금지** — 잘못된 요건 안내는 서비스 신뢰의 치명상

### 5.4 RAG
- 임베딩: 조문/항목 단위 청크, 비자코드·언어 메타데이터 필터
- 검색: 하이브리드(키워드+벡터), 비자코드 확정 시 해당 코드 우선
- 답변에 source URL + 갱신일 표기

## 6. 데이터 모델 (서비스 DB)

```
users        id, email, name, nationality, lang, current_visa, visa_expiry, phone
cases        id, user_id, visa_code, application_type, stage(§2의 0~10),
             assignee, quote_amount, created_at
case_events  case_id, stage_from, stage_to, actor, note, at          ← 타임라인
intake       case_id, slot_key, value, source(chat/form), confirmed_by_user
conversations case_id?, user_id, messages(jsonb), summary
checklist    case_id, doc_master_id, status, reviewer_note
files        checklist_id, s3_key(암호화), ocr_result, uploaded_at
```

민감정보(여권번호 등)는 컬럼 레벨 암호화, 파일은 S3 SSE + 서명 URL(만료 5분).

## 7. 시스템 아키텍처

```
[모바일 웹 (Next.js PWA, i18n)]      [관리자 웹 (Next.js)]
            │  REST/WebSocket             │
            └────────────┬────────────────┘
                   [API 서버 (FastAPI)]
          ┌──────────┬───────┴────────┬─────────────┐
   [PostgreSQL]  [S3 스토리지]   [챗봇 오케스트레이터]   [알림 워커]
   (+pgvector)   (서류 파일)     Claude API + 룰엔진    (이메일/푸시/카카오)
                                     │
                          [지식베이스 파이프라인]
                          크롤러/공공API → diff → 검수큐 → 임베딩
```

| 선택 | 근거 |
|---|---|
| Next.js PWA | 앱스토어 없이 홈화면 설치·푸시, 다국어 SSR로 SEO 직결 |
| FastAPI + Postgres(pgvector) | 소규모 팀, RAG까지 단일 DB로 운영 단순화 |
| Claude API | 다국어 품질·긴 컨텍스트(대화+근거 주입), function calling으로 슬롯 추출 |
| 결제 | 국내 PG + 해외카드 지원 (Stripe 병행 검토) |

## 8. 개인정보·보안 요건 (필수)

- 개인정보처리방침 4개 언어 제공, 수집 항목·보관기간 명시 (사건 종결 후 N년 — 법정 보존과 정합)
- 민감정보(여권·범죄경력 관련 응답) 별도 동의
- 전송 TLS, 저장 암호화, 접근 로그, 직원 권한 분리 (담당자만 서류 열람)
- 챗봇 대화의 LLM 전송 시: 개인정보 마스킹 옵션 검토, 모델 학습 미사용 계약 조건 확인
- 삭제권 요청 처리 절차 (진행중 사건 예외 규정 포함)

## 9. 운영 프로세스 (사무소 내부)

| 항목 | 기준 |
|---|---|
| 신규 상담 리드 응대 | 영업일 24시간 내 (챗봇이 즉시 1차 응대, 사람 확인은 24h SLA) |
| 서류 검토 | 업로드 후 2영업일 내 승인/보완 통보 |
| 보완 요청 | 사유·예시 이미지 첨부 의무화 (반복 보완 최소화) |
| 접수 | 서류 완비 + 잔금 확인 후 3영업일 내 |
| 거절 대응 | 거절 사유서 분석 → 재신청/이의신청 옵션 상담 (변호사 업무로 전환, 별도 수임) |
| 이해충돌·수임 거절 | 위법 목적·허위서류 의심 시 수임 거절 기준 문서화 |
