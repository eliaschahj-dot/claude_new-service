# 원고레이더 — 잠재 원고 발굴 엔진 (Plaintiff Discovery Engine)

> 사건이 들어오길 기다리지 않고, 공개 데이터에서 사건을 먼저 발굴하는 리걸테크 MVP.

기존 법률서비스는 의뢰인이 '문제가 터진 뒤' 찾아오는 반응형입니다. 원고레이더는 이를 뒤집어,
공개 데이터(전자공시 · 행정처분/과징금 · 리콜 · 집단민원 · 판결문 · 뉴스)를 상시 스캔해
**아직 자신이 청구권을 가진 줄도 모르는 피해자 집단(코호트)** 을 먼저 찾아내고,
수임 우선순위를 점수화하여 제시합니다. 미국 mass tort 리드젠의 핵심 엔진을 한국 공개
데이터 인프라 위에 구현하는 모델입니다.

## 실행

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
# → http://localhost:8000
```

### 실시간 연동 (선택)

API 키를 환경변수로 넣으면 해당 컴포넌트가 데모 시드에서 실시간 연동으로 전환됩니다.
키가 없으면 전부 데모 모드로 동작하므로 아무 설정 없이도 실행됩니다.

| 환경변수 | 전환되는 컴포넌트 | 발급처 |
|---|---|---|
| `DART_API_KEY` | 전자공시 수집 (OpenDART 공시검색) | [opendart.fss.or.kr](https://opendart.fss.or.kr) — 무료 즉시 발급 |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` | 뉴스 수집 (네이버 검색 API) | [developers.naver.com](https://developers.naver.com) |
| `ANTHROPIC_API_KEY` | LLM 구조화 추출 (미설정 시 규칙 기반 폴백) | [platform.claude.com](https://platform.claude.com) |
| `WONGO_LLM_MODEL` | 추출 모델 변경 (기본 `claude-opus-4-8`) | — |
| `WONGO_LOOKBACK_DAYS` | 라이브 수집 조회 기간 (기본 30일) | — |

```bash
export DART_API_KEY=...
export NAVER_CLIENT_ID=... NAVER_CLIENT_SECRET=...
export ANTHROPIC_API_KEY=...
uvicorn app.main:app
# 재수집: curl -X POST localhost:8000/api/refresh
```

## 파이프라인

```
┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ ① 수집        │ → │ ② 클러스터링   │ → │ ③ 스코어링    │ → │ ④ 액션        │
│ 9개 소스 커넥터│   │ 동일 피고+원인 │   │ 우선순위 0~100│   │ 수임 캠페인    │
│ (ingest.py)  │   │ (cluster.py) │   │ (scoring.py) │   │ 초안 생성      │
└──────────────┘   └──────────────┘   └──────────────┘   └──────────────┘
```

**① 수집** — 소스별 커넥터가 동일 인터페이스로 신호를 수집합니다.
**OpenDART(전자공시 검색)와 네이버 뉴스 검색 API는 실연동 구현이 완료**되어 키만
넣으면 라이브로 동작합니다 (`app/engine/ingest.py`의 `DartConnector`,
`NaverNewsConnector`). 나머지 소스(공정위 의결서, 금감원 제재/분조위, KISCON
행정처분, 소비자24 리콜 API, 개인정보위 처분, 판결서 열람, 국민신문고/커뮤니티)는
데모 모드이며 연동 대상 채널이 코드에 명시되어 있습니다.

**①.5 구조화 추출** — 라이브로 수집된 원시 이벤트(공시 제목, 기사 본문)를
LLM(Claude, 구조화 출력)이 (잠재 피고 · 원인 요약 · 사건 유형 · 중대성 ·
증거강도 · 피해규모 · **동일 원인 시그니처 cause_key**)로 변환합니다
(`app/engine/extract.py`). 관련성 없는 이벤트(실적공시, 광고 기사)는 이 단계에서
걸러집니다. `ANTHROPIC_API_KEY`가 없으면 키워드 규칙 기반 폴백으로 동작합니다.

**② 클러스터링** — 신호를 cause_key 기준 '동일 피고 + 동일 원인'으로 묶어
코호트를 만듭니다. 변호사가 검토한 메타(시드 6건)가 없는 신규 클러스터는
LLM이 법률 검토 **초안**(법적 근거 후보, 시효 유의점, 규모 추정)을 자동 생성해
"자동 초안 — 변호사 검토 대기" 상태로 대시보드에 올립니다.
→ *같은 시공사·같은 자재 대체 피해를 본 다른 발주처를 자동으로 묶으면 단건이 집단사건이 되는 지점.*

**③ 스코어링** — 수임 우선순위 점수:

| 구성 | 배점 | 내용 |
|---|---|---|
| 증거 강도 | 30 | 행정처분·판결·리콜 등 민사에서 원용 가능한 공적 확인 |
| 사건 규모 | 25 | 추정 총 청구액 (로그 스케일) |
| 신호 응집 | 15 | 독립 소스 수 — 여러 기관이 같은 사실을 가리키는가 |
| 시효 긴급 | 15 | 소멸시효 잔여 6~24개월 골든타임에 최고점 |
| 피고 자력 | 15 | 집행 가능성 (상장·자산 규모 프록시) |

**④ 액션** — 코호트별 수임 캠페인 초안(안내문 + 피해자 확인 랜딩)을 생성합니다.
초안은 배포 버튼이 없으며, **변호사 광고규정 심사 대기** 상태로만 생성됩니다.

## API

| 엔드포인트 | 설명 |
|---|---|
| `GET /api/stats` | KPI + 30일 신호 추이 |
| `GET /api/cohorts` | 코호트 목록 (점수순) |
| `GET /api/cohorts/{id}` | 코호트 상세 + 근거 신호 타임라인 |
| `GET /api/signals` | 원시 신호 피드 |
| `GET /api/sources` | 데이터 소스 상태 |
| `POST /api/cohorts/{id}/campaign` | 수임 캠페인 초안 생성 |

## 컴플라이언스 유의사항 (실서비스 전 필수 검토)

- **변호사법 제34조** (비변호사 동업·소개료 금지): 엔진을 변호사/로펌이 직접 운영하는
  내부 도구로 설계해야 하며, 제3자가 사건을 알선하고 대가를 받는 구조가 되지 않도록
  사업 구조 설계가 선행되어야 합니다.
- **대한변협 변호사 광고에 관한 규정**: 특정 사건 피해자 대상 안내는 광고 심사 대상.
  본 MVP는 캠페인 산출물을 '심사 대기 초안'으로만 생성하도록 워크플로우를 강제합니다.
- **개인정보보호법**: 수집 대상을 공개 데이터로 한정하고, 피해자 정보는 본인이 확인
  페이지에 직접 입력하는 opt-in 구조만 사용합니다.
- 판결문 데이터는 판결서 인터넷열람 제도의 이용 조건을 준수해야 합니다.

## 데모 데이터

`app/seed_data.py`의 모든 기업명·사건·처분은 **시연을 위해 창작된 가상의 것**으로,
실존 기업·사건과 무관합니다. 6개 시나리오(건설하자 자재대체, 사모펀드 불완전판매,
배터리 리콜, 하도급 부당감액, 개인정보 유출, 분식회계)는 각각 실제 한국에서 반복 발생하는
사건 유형의 구조를 본떠 만들었습니다.
